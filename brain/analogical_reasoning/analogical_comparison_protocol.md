# Analogical Comparison Protocol v1

## Recommended Approach

Analogical Comparison Protocol v1 governs how the Brain compares pricing systems after related cases have already been retrieved.

This protocol is not about what looks similar. It is about what shares causal monetization structure.

Surface pricing similarity is insufficient. Shared industry is insufficient. Shared subscription form is insufficient.

The Brain must compare:

- Bill-changing logic.
- Risk transfer.
- Buyer decision.
- Operational constraint.
- Strategic tradeoff.

Ontology provides vocabulary. Ontology Fit provides confidence. Retrieval selects candidates. Analogical Comparison explains structural similarity and structural difference.

This protocol does not replace ontology, ontology fit, or Brain Lookup retrieval policy. It explains comparison reasoning after retrieval has already happened.

## Why This Matters

Retrieval alone is not reasoning.

Without comparison governance, weak analogies become misleading, surface similarity dominates, ontology labels become overextended, and strategy lessons transfer incorrectly.

This protocol exists to:

- Identify shared causal structure.
- Identify non-transferable assumptions.
- Clarify analogy strength.
- Reduce false analogy risk.
- Support future reasoning engine quality.

A good analogy transfers mechanism. A dangerous analogy transfers surface appearance.

## Standard Comparison Structure

Use this reusable structure when comparing two pricing systems:

```md
## Analogical Comparison

Case A:
Case B:

Shared causal structure:
Shared bill-changing logic:
Differing trigger mechanism:
Differing risk transfer:
Differing buyer psychology:
Differing operational constraint:
Transferable lesson:
Dangerous overgeneralization:
Analogy strength:
- strong analogy
- partial analogy
- contrast analogy
- ontology stress analogy
```

Use these analogy strength definitions:

| Analogy Strength | Guidance |
| --- | --- |
| `strong analogy` | Shared primary decision pattern and similar trigger logic. |
| `partial analogy` | Shared structure, but important differences limit transfer. |
| `contrast analogy` | Surface similarity exists, but the causal engine differs. |
| `ontology stress analogy` | The comparison reveals ontology weakness or missing vocabulary. |

## Comparison Rules

- Compare causal structure before industry.
- Compare bill trigger before pricing surface.
- Compare risk transfer before feature similarity.
- Do not treat subscription form as proof of shared mechanism.
- Do not treat shared customer segment as proof of shared monetization logic.
- Always identify what should not transfer.
- If analogy is weak, say so explicitly.
- Contrast cases exist to prevent overgeneralization.
- Shared pricing unit does not guarantee shared decision pattern.
- Shared UI or packaging does not imply shared economics.
- The goal is strategic transfer, not textual similarity.

## Worked Examples

### Example 1: AWS Reserved Instances vs Gym annual membership

```md
## Analogical Comparison

Case A: AWS Reserved Instances / Savings Plans
Case B: Gym annual membership

Shared causal structure:
Both use predictability exchange. The buyer commits in advance, and the seller receives more predictable demand or revenue.

Shared bill-changing logic:
Spend changes when the buyer chooses commitment instead of flexibility. Lower unit economics are exchanged for demand predictability.

Differing trigger mechanism:
AWS pricing is triggered by infrastructure usage commitment and coverage choices. Gym membership is triggered by access commitment over a membership period.

Differing risk transfer:
AWS transfers infrastructure utilization risk to the buyer. Gym membership transfers behavioral attendance and underuse risk to the member.

Differing buyer psychology:
AWS buyers reason about workload planning, discount coverage, and cloud spend optimization. Gym members reason about habit formation, motivation, and expected attendance.

Differing operational constraint:
AWS manages cloud capacity and demand predictability. Gyms manage facility access, crowding, and fixed-location capacity.

Transferable lesson:
Commitment pricing reduces uncertainty for the seller while giving the buyer lower or simpler economics.

Dangerous overgeneralization:
Customer psychology and operational constraints differ significantly; cloud workload utilization is not the same as human attendance behavior.

Analogy strength:
strong analogy
```

### Example 2: HP Instant Ink vs OpenAI API token pricing

```md
## Analogical Comparison

Case A: HP Instant Ink
Case B: OpenAI API token pricing

Shared causal structure:
Both monetize customer activity through usage-linked value capture.

Shared bill-changing logic:
Spend rises as customer activity consumes a metered unit: printed pages for HP and tokens for OpenAI API usage.

Differing trigger mechanism:
HP uses allowance boundaries, rollover behavior, and overage logic. OpenAI API token pricing is closer to continuous metered consumption.

Differing risk transfer:
HP exposes customers to overage risk when page usage crosses predefined allowances. OpenAI exposes developers to usage growth risk as application activity and model choices consume more tokens.

Differing buyer psychology:
HP customers manage plan allowances and avoid surprise overages. OpenAI API customers manage product behavior, model selection, and unit economics at application scale.

Differing operational constraint:
HP must support replenishment, ink supply, and page-plan economics. OpenAI must support compute-intensive metered inference and model usage.

Transferable lesson:
Usage-based pricing scales monetization with customer activity.

Dangerous overgeneralization:
Threshold psychology differs from continuous metering; allowance management is not the same as token-level consumption management.

Analogy strength:
partial analogy
```

### Example 3: Airbnb service-fee incidence vs Shopify transaction pricing

```md
## Analogical Comparison

Case A: Airbnb service-fee incidence
Case B: Shopify transaction pricing

Shared causal structure:
Both involve platform activity monetization. Value is captured as economic activity flows through platform infrastructure.

Shared bill-changing logic:
Spend or platform take changes around mediated transactions: bookings in Airbnb and commerce or payment activity in Shopify.

Differing trigger mechanism:
Airbnb emphasizes where fees are seen, absorbed, displayed, or deducted. Shopify emphasizes transaction activity, payment configuration, and commerce infrastructure.

Differing risk transfer:
Airbnb's key risk is conversion and fairness perception when fee incidence moves. Shopify's key risk is merchant economics as payment and commerce activity scale.

Differing buyer psychology:
Airbnb participants respond to visible fee burden and perceived fairness. Shopify merchants reason about platform dependency, payment configuration, and cost of commerce infrastructure.

Differing operational constraint:
Airbnb must balance guest conversion, host payout, and marketplace liquidity. Shopify must support merchant selling infrastructure, payment flows, and platform monetization.

Transferable lesson:
Platforms capture value through mediated economic activity.

Dangerous overgeneralization:
Fee visibility is not the same as transaction infrastructure economics.

Analogy strength:
partial analogy
```

### Example 4: Apple One bundle pricing vs Peloton hardware-to-membership

```md
## Analogical Comparison

Case A: Apple One bundle pricing
Case B: Peloton hardware-to-membership

Shared causal structure:
Both create recurring monetization after an entry decision.

Shared bill-changing logic:
Spend changes when the buyer enters a recurring access relationship rather than treating the purchase as a one-time transaction.

Differing trigger mechanism:
Apple One is triggered by bundle subscription adoption across multiple service entitlements. Peloton is triggered by hardware ownership that makes a recurring membership valuable or necessary.

Differing risk transfer:
Apple One creates underuse risk across a portfolio of services. Peloton creates underuse risk around connected fitness membership and hardware-enabled participation.

Differing buyer psychology:
Apple One buyers evaluate whether the combined services justify the bundle price. Peloton buyers evaluate whether hardware plus membership will sustain a fitness habit.

Differing operational constraint:
Apple manages a heterogeneous service portfolio and bundle economics. Peloton manages connected hardware, content, and membership engagement.

Transferable lesson:
Entry mechanism shapes the long-term monetization path.

Dangerous overgeneralization:
Bundled entitlement logic differs from trigger-path monetization.

Analogy strength:
contrast analogy
```

### Example 5: Uber surge pricing vs HP Instant Ink

```md
## Analogical Comparison

Case A: Uber surge pricing
Case B: HP Instant Ink

Shared causal structure:
Both expose customers to variable spending linked to customer activity or purchase conditions.

Shared bill-changing logic:
The customer pays more when the relevant condition changes: local demand-supply pressure for Uber and page usage crossing allowance boundaries for HP.

Differing trigger mechanism:
Uber uses real-time market repricing based on demand, supply, and capacity pressure. HP uses predefined allowance boundaries, rollover rules, and overage pricing.

Differing risk transfer:
Uber transfers dynamic market and peak-capacity price volatility to the rider at purchase time. HP transfers overage risk to customers whose printing exceeds plan boundaries.

Differing buyer psychology:
Uber riders face immediate price volatility and decide whether the ride is worth the current fare. HP customers choose a plan and manage usage against expected monthly needs.

Differing operational constraint:
Uber must balance marketplace liquidity and driver supply in real time. HP must manage replenishment economics and page-plan fairness.

Transferable lesson:
Both expose customers to variable spending.

Dangerous overgeneralization:
Dynamic market repricing is fundamentally different from threshold-based pricing.

Analogy strength:
ontology stress analogy
```

## Risks And Guardrails

| Risk | Guardrail |
| --- | --- |
| False analogy | Require shared causal structure and explicit non-transferable lessons. |
| Over-transfer | Always name the dangerous overgeneralization. |
| Surface pricing bias | Compare bill-changing logic before pricing surface. |
| Industry-category bias | Compare causal monetization structure before industry. |
| Excessive abstraction | Keep the comparison tied to bill trigger, risk transfer, buyer decision, operational constraint, and strategic tradeoff. |
| Ontology overreach | Use ontology stress analogy when the comparison reveals missing vocabulary or weak fit. |
| Process bloat | Prefer fewer high-quality analogies over many weak analogies. |
| Premature automation | Use manually before any schema, UI, database, or retrieval engine integration. |

The Brain should prefer fewer high-quality analogies over many weak analogies.
